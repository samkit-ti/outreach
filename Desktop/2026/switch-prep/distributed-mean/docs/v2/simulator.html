Distributed Mean — Design Lab

Race the algorithms considered in ITDs DM-001…DM-010. Same seed, same workers — different design decisions.

The request (from the interview prompt)

Design a system that assigns a large job across a fleet of workers and aggregates their outputs into one result: the index-wise mean of F files × C random numbers (1 < F < 100k, 1 < C < 1,000k). Constraints: a worker may hold at most 5 files at a time; workers run at different speeds — minimize idling; jobs with F > 5 must be split into multiple queue items; multiple jobs run concurrently; the system must decide when a job is finished. Bonus: worker count W configurable via API, and a live UI of system state.

Every lane runs the same job with the same worker speed profile and RNG seed — only the decision under test differs. Each lane is a Gantt strip: one row per worker, time flowing right, colored by task type. Gaps are idle time — the thing DM-002 exists to eliminate. Progress bars use DM-009's monotone file-coverage metric, so they never move backwards. The log narrates pairing decisions, lease expiries, and each lane's completion proof (count == F).

Parameters map to the prompt: F, C are the user's job inputs; W is the (bonus) configurable fleet size; K is the RAM constraint; the speed profile exercises the "different speeds" clause; drain-mode off shows why adaptive fan-in exists — the strict-5 variant deadlocks in the tail and the lane is flagged STUCK.
